# 1회 의도 리뷰

2026-10-16 사용자 합의에 따른 초기 구현 계약이다. PR 본문과 고정된 변경 전후 원문을 함께 읽어 개발 의도를 이해하고, 구현이 그 의도에 맞으며 기대 결과를 달성할 수 있는지 검토한다.

## 이번 실행 범위

한 번 고정한 입력을 한 번의 리뷰 실행으로 처리하고 비공개 결과를 저장한다. 내부의 관점 선택·초기 분석·최종 검토·필요한 재확인은 이 실행에 포함된다. PR 변경 감지에 따른 반복 리뷰와 게시 후 최신성 보강은 후속 작업이다.

기존 intent CLI의 명시적 평가 모드인 perspectives-v1을 사용한다. 이 모드는 저장소를 다시 수집하거나 대상 코드·빌드·테스트·hook을 실행하지 않으며, GitHub 게시기·대기열·Worker를 구성하지 않는다. 기존 declared-v1과 code-first-v2 입력·실행 계약은 별도로 보존한다.

## 초기 선택지

| 식별자 | 관점 | 검토 질문 |
| --- | --- | --- |
| problem_success | 문제와 성공 기준 | 누구의 어떤 상황이 문제이며, 무엇이 달라지면 해결인가? |
| intent_change | 목적과 변경의 대응 | 목적마다 구현이 있고 주요 변경마다 설명되는 이유가 있는가? |
| means_fit | 수단의 적합성 | 구현이 의도한 문제에 작용하며 원하는 해결 수준에 맞는가? |
| outcome_connection | 결과까지의 연결 | 구현의 효과가 실제 사용자·호출자·후속 처리에 도달하는가? |
| achievement_scope | 달성 범위 | 의도한 대상과 조건에서 빠짐없이, 과하지 않게 적용되는가? |
| preservation | 보존 조건 | 유지하려던 결과와 바꾸지 않겠다는 경계를 지키는가? |
| assumptions_tradeoffs | 전제와 절충 | 필요한 가정과 감수하는 손실이 목적에 맞는가? |
| supporting_evidence | 검증 근거 | 코드·테스트가 목적 달성에 대한 주장을 뒷받침하는가? |

원본 정의는 [도메인 카탈로그](../src/review_bot/domain/intent_perspectives.py)의 intent-perspectives/v1이다. 실제 실행에는 카탈로그 내용과 hash를 함께 보존한다.

## 역할과 실행 순서

1. 고정 입력의 schema·hash·원문 완전성을 검증하고, 전체 원문을 포함한 실제 리뷰 요청을 native 계측한다. 입력이 맞지 않으면 생성하지 않는다. 파일 생략·요약·절삭으로 한도를 맞추지 않는다.
2. Tev1이 PR 전체를 기준으로 각 관점에 적용·비적용·판단불가를 선택한다. 각 요청은 상태·고정 질문·세 선택지를 제공하며, 응답은 선택 문자 하나를 담은 작은 JSON 객체다. 현재 ModelClient의 JSON 응답 계약을 재사용한다. Tev1에 분석 계획·관계 목록·이유를 생성시키지 않는다.
3. 주 리뷰 LLM이 본문과 전체 base/head·제공된 테스트를 함께 읽고 초기 리뷰를 작성한다. Tev1의 판단불가도 이 단계에서 원문을 보고 재판정한다. 모든 관점의 적용 여부를 근거와 함께 기록하며 관점을 추가·제외할 수 있다.
4. 주 리뷰 LLM이 같은 원문과 검증된 초기 판단·누락 정보를 읽고 최종 검토한다. 기존 원문을 다시 해석한 것만으로도 판단을 정정할 수 있다. 판정이나 실패 조건을 바꿀 때 정정 이유를 요구하고 이전·이후 판단과 원문 근거를 보존한다.
5. 최종 평가에서 고정 범위의 원문 재확인이 요청되면 남은 예산 안에서 최대 한 번 더 검토한다. 모든 리뷰 요청에는 전체 준비 원문이 포함된다. 범위 밖 경로는 읽지 않고 요청과 정보 부족을 보존한다. 예산이 부족하거나 재확인 후에도 요청이 남으면 충분한 검토로 표시하지 않는다.

본문의 주장은 의도의 설명이며 코드와 대조할 대상이다. 코드에서 추정한 목적을 개발자의 실제 생각이나 확정 요구사항으로 승격하지 않는다. 복수 목적·의도적인 부분 해결·영향 완화도 가능하다. 더 좋은 대안이 있거나 본문이 부족하다는 사실만으로 코드 결함을 만들지 않는다.

## 정보 부족과 판단 정정

미해결 정보는 프로그램이 부여한 M 식별자로 단계 사이에 누적한다. 해결 또는 판단에 영향을 주지 않는 정보로 재분류하려면 명시적인 갱신과 원문 근거를 요구한다. 최종 응답에서 이전 누락을 생략하는 것만으로 해소되지 않는다.

현재 적용된 관점의 필요한 판단을 막는 미해결 정보는 부분 검토로 표시한다. 보조 자료 부족은 한계로 남기며 판단 가능한 결과를 보존한다. 실행의 최종 평가 존재, 범위 충분성, 지적 없음은 별도 값이다. 정보 부족은 코드 결함이 아니다.

인용은 제공된 evidence_id·행 범위만 받는다. 프로그램이 고정된 원문에서 SHA·경로·quote를 추출한다. 근거 없는 정정, 위조 인용, 범위 밖 원문 참조, 허용되지 않은 관점·context 식별자와 추가 필드는 거부한다. concern·conditional_risk에는 head 코드 근거와 구체적인 실패 조건이 필요하다.

## 호출과 사용량

기본 실행은 Tev1 선택 8회와 주 리뷰 2회다. 선택 응답은 각각 최대 16 출력 토큰이며, 관점별 자유 서술을 생성하지 않는다. 요청에 따라 주 리뷰의 원문 재확인 1회가 추가될 수 있다.

전체 기본 한도는 12회, 입력 131072 tokens, 실제 누적 작업 131072 tokens, 900초, 재확인 최대 1회다. 실제 시도와 계측 사용량을 합산하고 다음 필수 단계의 호출·출력 여유를 검사한다. 프로필의 byte·입력·출력 한도도 독립 적용한다. 전송·사용량 불명은 0으로 대체하거나 숨겨 재시도하지 않는다.

현재 me707-llamacpp와 macbook-llamacpp의 명시적 프로필을 지원한다. 같은 모델 그룹의 기존 SQLite HTTP admission을 사용하고, llama.cpp의 정확한 모델·컨텍스트·실제 생성 슬롯 1개를 확인한다. 불확실한 생성 기록을 임의로 해제하지 않는다.

## 결과와 사용자 설명

입력 IntentTaskInput과 ModelRequest는 schema 1이다. 새 결과는 schema 3, prompt version은 review-b/intent-perspectives-v1이다. 기존 v1/v2 결과를 새 결과로 재해석하지 않는다. 실행 키는 고정 입력·카탈로그·프롬프트·언어·모델 역할·한도·초기 선택을 반영한다.

사용자 결과는 파악한 개발 의도 → 구현과의 연결 → 달성 가능성 판단 → 필요한 확인 질문 순서다. ko가 기본이며 en을 명시할 수 있다. 모델 입력에도 언어를 전달한다. 원문 링크는 검증된 인용에서만 생성하며 모델이 쓴 HTML·링크·mention은 신뢰하지 않는다.

B 디렉터리에 input/result/scope/usage/validation/comment와 catalog.json, selection.json, perspectives.json, judgements.json, context.json, passes.json을 저장한다. 선택과 판단의 수정 이력, 미해결 정보와 해소 이력을 보존한다. 디렉터리는 0700, 파일은 0600이며 기존 결과를 덮어쓰지 않는다. publication은 artifact_only/not_attempted다.

최종 검토가 충분하면 CLI는 exit 0, 미실행·실패·부분 검토이면 exit 1이다. 부분 결과도 저장한다. 이 실행에는 결과 재사용이나 최신 PR로의 자동 재게시가 없다.

## 실행 예시

    rtk proxy uv run --locked --offline review-bot intent \
      --input /path/to/private/input.json \
      --output /path/to/private/review-001 \
      --pipeline perspectives-v1 --model-profile me707-llamacpp \
      --language ko --call-timeout-seconds 120

프로필의 endpoint·공유 상태 경로 준비는 README의 기존 운영 안내를 따른다. 비공개 자료·키·모델·실행 산출물은 커밋하지 않는다. 실제 테스트 명령과 결과는 [milestones](../milestones.md)에 기록한다. 구조·인용 검증과 자동화 회귀의 통과는 의미적 리뷰 정확성 보증이 아니다.
